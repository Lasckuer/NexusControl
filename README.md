# NexusControl 🐳

**NexusControl** — это современный, производительный и надежный Telegram-бот для удаленного мониторинга сервера и управления контейнерами Docker в режиме реального времени.

Построен на базе **Python 3.11+**, фреймворка **Aiogram 3**, асинхронного драйвера **aiosqlite** и неблокирующего взаимодействия с **Docker Engine API**.

---

## ✨ Возможности

### 📊 Мониторинг ресурсов сервера (Хоста)
- **Живой мониторинг в реальном времени:** автообновление сообщения с наглядными текстовыми индикаторами (прогресс-барами).
- Метрики:
  - Нагрузка процессора (CPU) и количество ядер.
  - Оперативная память (RAM): процент, использовано / доступно.
  - Дисковое пространство: процент и объем.
  - Сетевой трафик: входящие и исходящие байты.
  - Время непрерывной работы системы (Uptime) и версия ОС.

### 📦 Управление Docker-контейнерами
- **Пагинация и фильтрация:** удобная постраничная навигация по контейнерам с фильтрацией:
  - *Все*
  - *🟢 Включенные (Running)*
  - *🔴 Выключенные (Exited / Dead)*
- **Подробная карточка контейнера:**
  - Системное имя и читаемый алиас.
  - Статус и здоровье (*Healthcheck: Healthy / Unhealthy*).
  - Тег Docker-образа, дата создания и время последнего запуска.
  - IP-адреса контейнера и привязанные сетевые порты (*Port Bindings*).
  - Количество рестартов.
- **Действия над контейнерами:**
  - 🔄 **Перезапуск** (`restart`)
  - 🛑 **Штатная остановка** (`stop`)
  - ▶️ **Запуск** (`start`)
  - ⏸ **Приостановка / Возобновление** (`pause` / `unpause`)
  - 💀 **Принудительное завершение** (`kill`) с диалогом подтверждения
- **Логи контейнера:**
  - Быстрый просмотр последних 50, 100 или 300 строк прямо в чате.
  - Выгрузка полного лог-файла в формате `.log` документом в Telegram.
- **Живой монитор контейнера:**
  - Автообновление CPU%, RAM (с вычитанием кэша страниц для точности), I/O сети.

### 🚨 Интеллектуальная система алертов
- **Мониторинг падений контейнеров:** мгновенное уведомление в Telegram при аварийной остановке контейнера.
- **Умное подавление ложных тревог:** бот запоминает штатные остановки, инициированные администратором через бота, и не спамит алертами.
- **Алерты аппаратных ресурсов:**
  - Превышение порогов CPU, RAM, Диска (настраивается в `.env`).
  - Механизм гистерезиса (предотвращает спам уведомлениями при колебаниях около порога).
  - Уведомление о нормализации нагрузки.

### ♻️ Очистка Docker (Docker Prune)
- Защита от случайного удаления данных: двухуровневое подтверждение в Telegram.
- Варианты:
  - *Стандартная очистка (без томов):* удаление остановленных контейнеров, висячих образов и неиспользуемых сетей.
  - *Полная очистка (+ тома):* очистка неиспользуемых Volumes с отдельным предупреждением.
- Отчет об объеме освобожденного места на диске.

### 🛡 Безопасность и Архитектура
- **AdminAuthMiddleware:** автоматическая блокировка неавторизованных пользователей на входе.
- **Поддержка списка администраторов:** можно указать несколько Telegram ID через запятую (`ADMIN_IDS`).
- **Неблокирующий Event Loop:** все тяжелые сетевые и системные операции Docker / psutil выполняются в отдельных потоках через `asyncio.to_thread`.
- **Защита от лимитов Telegram:** интеллектуальное сравнение изменений текста перед отправкой запроса к Telegram API, исключающее ошибки `message is not modified`.
- **Безопасное экранирование:** генерация сообщений в безопасном HTML-формате.

## 🚀 Быстрый запуск

### 1. Клонирование и настройка окружения

```bash
git clone https://github.com/Lasckuer/NexusControl.git
cd NexusControl
cp .env.example .env
```

Отредактируйте `.env`:
```ini
# Токен бота, полученный у @BotFather
BOT_TOKEN=123456789:AAFg...

# Telegram ID администраторов (через запятую)
ADMIN_IDS=123456789,987654321

# Опционально: уровень логирования
LOG_LEVEL=INFO
```

### 2. Запуск через Docker Compose (Рекомендуется)

```bash
docker compose up -d --build
```

Бот запустится в фоновом режиме, подключившись к локальному Docker-сокету `/var/run/docker.sock`.

### 3. Локальный запуск (для разработки)

```bash
python -m venv venv
# Linux / macOS:
source venv/bin/activate
# Windows:
.\venv\Scripts\activate

pip install -r requirements.txt
python main.py
```

## 🧪 Запуск тестов

В проект встроен полный набор тестов на `pytest`:

```bash
python -m pytest tests/ -v
```

Тесты полностью изолированы и не требуют запущенного локального Docker-демона благодаря мокам и фикстурам.

## 📂 Структура проекта

```
NexusControl/
├── app/
│   ├── config.py                 # Централизованная конфигурация и валидация
│   ├── database/
│   │   └── db.py                 # Асинхронное хранилище (aiosqlite)
│   ├── handlers/
│   │   ├── common.py             # Команды /start, /help, регистрация подсказок
│   │   ├── containers.py         # Управление контейнерами, логи, пагинация
│   │   ├── messages.py           # Кнопки главного меню и диалоги подтверждения
│   │   └── scheduler.py          # Таймеры мониторинга, алерты падений и нагрузки
│   ├── keyboards/
│   │   ├── inline.py             # Инлайн-клавиатуры и диалоги
│   │   └── reply.py              # Главное меню Telegram
│   ├── middlewares/
│   │   └── auth.py               # Middleware авторизации администраторов
│   ├── services/
│   │   ├── docker_service.py     # Асинхронный Docker Engine сервис
│   │   └── system_service.py     # Асинхронный сбор метрик хоста (psutil)
│   └── utils/
│       ├── aliases.py            # Названия и алиасы контейнеров
│       └── formatters.py         # Безопасный HTML, прогресс-бары, байты, uptime
├── tests/                        # Модульные и интеграционные тесты (pytest)
├── docker-compose.yml            # Конфигурация запуска Docker
├── Dockerfile                    # Сборка контейнера
├── logger.py                     # Структурированное логирование
├── main.py                       # Точка входа бота
├── pytest.ini                    # Настройки тестового фреймворка
└── requirements.txt              # Зависимости проекта
```
